# ระบบพยากรณ์อากาศและภัยธรรมชาติ

เว็บแอปพลิเคชันสำหรับพยากรณ์อากาศ ทำนายฝน วิเคราะห์ความเสี่ยงน้ำท่วม ติดตามแผ่นดินไหว และน้ำขึ้นน้ำลง
เป็นเว็บฝั่งเบราว์เซอร์ (HTML/CSS/JavaScript) ใช้ข้อมูลจริงจาก API สาธารณะ

## วิธีรัน

```bash
python server.py
```

แล้วเปิด http://localhost:8080

`server.py` ให้บริการไฟล์ของเว็บ และเป็นตัวกลาง (proxy) ให้ API ภาพเรดาร์ของกรมฝนหลวงและการบินเกษตร ซึ่งไม่อนุญาตให้เบราว์เซอร์เรียกโดยตรง (ไม่มี CORS)
ถ้ารันด้วย `python -m http.server` แทน ทุกแท็บยังใช้งานได้ ยกเว้นภาพเรดาร์ของกรมฝนหลวงฯ

### การใช้ข้อมูล ThaiWater ช่วยทำนาย

- **ทำนายฝน**: เปรียบเทียบฝนตรวจวัดจริงจากสถานีใกล้เคียง (รัศมี 20–40 กม.) กับค่าแบบจำลอง และเกณฑ์เตือนภัยของแต่ละโซน
- **วิเคราะห์น้ำท่วม**: เพิ่ม 3 ปัจจัย — ฝนตรวจวัดจริงเทียบเกณฑ์โซน, ระดับน้ำจริงในลำน้ำ (รัศมี 30 กม.), เขื่อนใกล้เคียงที่น้ำมาก (รัศมี 100 กม.)
- ค่าฝนสูงผิดปกติที่สถานีข้างเคียงไม่ยืนยัน จะถูกลดน้ำหนักและแจ้งให้ตรวจสอบ
- ข้อมูล ThaiWater เป็นข้อมูลระดับประเทศ แคชไว้ 15 นาที (กดรีเฟรชเพื่อโหลดใหม่)

### พยากรณ์ฝนระยะสั้นจากเรดาร์ (nowcast)

1. ดึงภาพเรดาร์ RainViewer 7 เฟรมล่าสุด (60 นาที) ในโดเมน 3×3 ไทล์รอบตำแหน่ง (~900 กม., ~1.2 กม./px) แล้วถอดสีเป็นค่า dBZ ด้วยตารางสีทางการ
2. ประมาณเวกเตอร์การเคลื่อนตัวด้วย block matching (บล็อก 48 px, ค้นหา ±6 px, ความแม่นยำระดับย่อยพิกเซล) จาก 3 คู่เฟรมล่าสุด
3. เลื่อนภาพล่าสุดไปข้างหน้าทีละ 10 นาที ถึง 90 นาที (semi-Lagrangian)
4. โอกาสฝน = สัดส่วนพื้นที่ ≥ 20 dBZ ในรัศมี ~12 กม. (neighbourhood probability) — เหมาะกับฝนฟ้าคะนองที่ตำแหน่งแน่นอนคาดเดายาก
5. ผสมกับโอกาสฝนของแบบจำลอง Open-Meteo: น้ำหนักเรดาร์ลดเป็นเส้นตรงจาก 100% → 0% ภายใน 90 นาที
6. ทุกครั้งที่คำนวณ จะทดสอบย้อนหลังโดยทำนายจากภาพ −30 นาทีแล้วเทียบกับภาพจริงล่าสุด และแสดงผลบนหน้าเว็บ

ทดสอบระหว่างพัฒนา (3 พื้นที่: กรุงเทพฯ, สงขลา, นครสวรรค์) — Brier score เทียบกับการคงสภาพ (persistence):
+30 นาที ดีกว่า ~30%, +60 นาที ดีกว่า ~30%, +90 นาที ใกล้เคียงค่าภูมิอากาศ จึงส่งต่อให้แบบจำลอง

ข้อจำกัด: RainViewer (บริการฟรี) ให้ข้อมูลถึงซูม 7 และย้อนหลัง 2 ชม.; ฝนฟ้าคะนองช่วงบ่ายที่ก่อตัวในพื้นที่ (ไม่เคลื่อนที่) การเลื่อนภาพช่วยได้น้อย ความแม่นยำส่วนใหญ่มาจากการคิดแบบย่าน

### แบบจำลองทำนาย PM2.5

1. ดึงค่า PM2.5 ตรวจวัดจริงรายชั่วโมงย้อนหลัง 14 วันของสถานีที่เลือก (Air4Thai)
2. ตัวแปรต้น 11 ตัว: PM2.5/CO/NO₂/AOD จาก CAMS, ความสูงชั้นผสมอากาศ, ลม, ความชื้น, ฝนสะสม 6 ชม., อุณหภูมิ, ช่วงเวลาของวัน
3. Ridge regression บน log(PM2.5) (ตัวแปรปรับมาตรฐาน, λ = 3)
4. ทดสอบกับ 48 ชม. ล่าสุดที่แบบจำลองไม่เคยเห็น แล้วเลือกวิธีที่แม่นที่สุดของสถานีนั้น: แบบจำลองสถิติ / CAMS / ค่าเฉลี่ยทั้งสอง
5. ช่วงความเชื่อมั่น ~80% จากความคลาดเคลื่อนในช่วงทดสอบ

ทดสอบกับ 8 สถานีสุ่ม (ทำนายล่วงหน้า 72 ชม.): MAE 3.8 µg/m³ เทียบกับ CAMS โดยตรง 5.0 µg/m³

### คีย์ API

คีย์ทั้งหมดอยู่ต้นแต่ละโมดูลใน `js/app.js` และมองเห็นได้ใน source ของหน้าเว็บ (เป็นเว็บฝั่งเบราว์เซอร์ล้วน):
`WAQI_TOKEN`, `FIRMS_KEY` (NASA FIRMS MAP KEY, จำกัด 5,000 คำขอ/10 นาที), `GISTDA_KEY` (GISTDA API Gateway)

### ข้อจำกัดของ API ไฟป่าที่พบระหว่างพัฒนา

- NASA FIRMS area API รับได้ครั้งละ 1–5 วัน → แอปแบ่งช่วงเวลาเป็นก้อนละ 5 วันอัตโนมัติ; country API ใช้งานไม่ได้แล้ว จึงแยกประเทศด้วยเขตแดน Natural Earth
- GISTDA ส่งข้อมูล ~1.6 KB/จุด และไม่บีบอัด → จำกัดการดาวน์โหลดที่ 6,000 จุด/ครั้ง (จำนวนรวมยังถูกต้องจาก `numberMatched`)
- GISTDA burn scar มีหลายพันแปลงต่อจังหวัด → โหลดเฉพาะจังหวัดที่เลือก (สูงสุด 5,000 แปลง)
